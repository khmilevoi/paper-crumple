# Independent Reatom Adapter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Реализовать независимый `@paper-crumple/reatom` с моделями scene/resource/view/run и отображением через существующий React-пакет.

**Architecture:** Core получает дешёвые semantic notifications и отдельный stable `@paper-crumple/core/bindings` с framework-free controllers, извлечёнными из существующей React orchestration. React сохраняет свои публичные hooks и их покадровое поведение; Reatom управляет собственными моделями и использует progress только по подписке. Общий минимальный render-контракт связывает модели с `<Crumple>` без второго владельца lifecycle.

**Tech Stack:** TypeScript, pnpm workspace, Vitest unit/types/browser, React 19, Reatom v1001, tsdown, существующие CPU/smooth benchmark harnesses.

**Spec:** `docs/design/2026-09-11-reatom-design.md` — читать полностью вместе с планом.

## Global Constraints

- `@paper-crumple/react` работает без Reatom; `@paper-crumple/reatom` работает без React.
- Основной Reatom entrypoint зависит от core и Reatom, но не загружает paper/motion.
- Отдельные обёртки SDF, renderers, resamplers, caches, meshes и прочих low-level ресурсов не входят в v1.
- `core/unstable`, новые SSR-возможности и перестройка всего API библиотеки вне scope.
- Число подписчиков atoms никогда не определяет владение GPU-ресурсами.
- `scene.dispose()` окончательно завершает принадлежащие ей операции и ресурсы.
- Для `picture.swap` проектное правило — последний запрос данного view заменяет предыдущий, без очереди.
- Частичные `failed[]` остаются данными report, не искусственной generic error.
- Reatom frame progress opt-in; существующие React hooks продолжают читать каждый `step`.
- Модель привязана к Reatom context/frame своего владельца; callback не создаёт новый context.start. GPU closure не разделяется между независимыми contexts.
- Raw `play/crumpleTo/swapTo` запускаются синхронно; async completion наблюдает `.done`.
- Ошибки core остаются Result-значениями; throw допускается только в именованной conversion boundary Reatom.
- Published manifests содержат `dependencies: {}`; runtime-зависимости оформляются peerDependencies, локальные сборки — devDependencies.
- Все shell-команды начинаются с `rtk`. Не делать cross-package `src` imports; собирать core перед межпакетными тестами.
- Node проекта: `^22.18.0 || >=24.11.0`; pnpm: `10.14.0`; TypeScript workspace: `5.9.3`. Не повышать floor остальных пакетов ради Reatom.
- Числовой performance budget не согласован; измерения пока не проводились.

## Общие контракты, фиксируемые этим планом

Ниже полные boundary signatures. Внутренние Reatom types выводить из фабрик через `ReturnType`; не воспроизводить вручную расширенные generic signatures Reatom.

```ts
// packages/core/src/changes.ts
export type ChangeArea = 'lifecycle' | 'settings' | 'resources' | 'content' | 'geometry' | 'state'
export interface ChangeSource {
  subscribe(area: ChangeArea, listener: () => void): () => void
  revision(area: ChangeArea): number
}
export interface ChangePublisher extends ChangeSource {
  emit(area: ChangeArea): void
  batch<T>(operation: () => T): T
  clear(): void
}
export function createChanges(): ChangePublisher
```

`StageCommon`, `View`, `Sprite` получают readonly `changes: ChangeSource`. Источник уведомления уже определяет объект; listener не получает allocation-heavy payload. Неприменимая область никогда не уведомляется. Старый `.on()` и error payload не меняются. `revision(area)` — O(1) номер semantic изменения; меняется даже без listeners, без payload/snapshot allocation. При batching номер меняется вместе с фактической mutation до callback delivery, чтобы синхронный direct read внутри операции не видел старый cache. Нет progress increments в semantic revisions.

Read bridges используют native `reatomObservable<T>` и возвращают `Atom<T>`, без собственного ReadSelector/invalidation middleware. Producer getState перечитывается на каждом прямом вызове; subscribe подключается через native withConnectHook и возвращает cleanup. Async data/error остаются native atom references. `render()` — native observable atom RenderValue с identity caching по semantic revisions, а не новый object при каждом чтении. Подтверждено upstream `packages/core/src/methods/reatomObservable.ts`; Task 6 compile/runtime-check выбранной installed версии обязателен. Это уточнение механизма чтения сохраняет одобренный callable DX и native atom API.

```ts
// packages/core/src/bindings/types.ts
import type {
  Aborted, AddError, BlitStage, DirectStage, HostedStage, StageCommon,
  BlitTarget, DirectTarget, HostedTarget, Events, Knobs, PlayOptions, PlayResult,
  PoseRef, Run, Sprite, SpriteSource, StageEvent, SwapResult, View, ViewFrame,
} from '../index.js'
export type BindingStage = BlitStage | DirectStage | HostedStage
export type TargetFor<S extends BindingStage> = S extends BlitStage ? BlitTarget
  : S extends DirectStage ? DirectTarget : HostedTarget
export type SceneFactory<S extends BindingStage = BlitStage> = (
  signal: AbortSignal,
  onError: (event: StageEvent<'error'>) => void,
) => Promise<S | Error | Aborted>
export interface RenderValue {
  readonly ref: (canvas: HTMLCanvasElement | null) => void
  readonly shown: string | null
  readonly frameStyle: Readonly<{ width: string; height: string; left: string; top: string }> | null
}
export interface Acquisitions {
  acquire(key: string, source: SpriteSource, pin?: true): Promise<Sprite | AddError | Aborted>
  dispose(): void
}
export type AcquisitionStage = Pick<StageCommon, 'get' | 'prepare' | 'add'>
export interface SceneController<S extends BindingStage = BlitStage> {
  readonly stage: S | null
  readonly disposed: boolean
  ensure(): Promise<S | Error | Aborted>
  dispose(): void
}
export interface RequestGate {
  readonly signal: AbortSignal
  current(): boolean
  adopt(run: Run<PlayResult | SwapResult>): void
  cancel(): void
  finish(): void
}
export interface TargetViewController<T extends BlitTarget | DirectTarget | HostedTarget> {
  readonly view: View | null
  readonly requested: string | null
  readonly pending: boolean
  readonly error: Error | null
  readonly frame: ViewFrame | null
  attach(target: T | null): void
  request(key: string, source: SpriteSource, options?: { pin?: true; signal?: AbortSignal }): Promise<Sprite | Error | Aborted>
  play(from: PoseRef, to: PoseRef, options?: PlayOptions): Run<PlayResult> | Error
  draw(pose: PoseRef): Error | undefined
  set(patch: Knobs): Error | undefined
  stop(): void
  dispose(): void
}
export interface ViewController extends TargetViewController<BlitTarget> {
  readonly ref: RenderValue['ref']
}
```

`ViewController.error` — существующее domain request outcome для React snapshot; Reatom не копирует его в свой второй async error atom. Reatom request `.error` берётся из преобразованного return value. `BindingStage` — новый alias существующих трёх интерфейсов, не выдуманный export core `Stage`. Scene/resource generic по S; общая acquisition требует только AcquisitionStage. Noncanvas view сохраняет `attach(DirectTarget|null)` или `attach(HostedTarget|null)`, Blit view — `attach(BlitTarget|null)` и стабильный `ref`, переводящий canvas в BlitTarget. Только Blit view предоставляет RenderValue и `render()`; отсутствие canvas никогда не блокирует Direct/Hosted target.

- [ ] **Step 3:** Реализовать publisher: фиксированная таблица областей; listener storage создаётся при первой подписке; depth и dirty bits создают operation batching. Сначала O(1) semantic revision increment, затем нулевая подписка возвращается до создания payload/итераторов. `finally` завершает batch при выброшенном пользовательском callback, не проглатывая его ошибку.
```ts
const areas: readonly ChangeArea[] = ['lifecycle', 'settings', 'resources', 'content', 'geometry', 'state']
// Ключевой путь emit: не создавать массив listeners при их отсутствии.
function mark(area: ChangeArea): void {
  const index = areas.indexOf(area)
  revisions[index] = (revisions[index] ?? 0) + 1
  if (listeners[index]?.size) dirty |= 1 << index
}
```

В этой реализации `listeners` — `(Set<() => void> | undefined)[]` длины `areas.length`, `revisions` — number[] нулей той же длины, `dirty` — number, `depth` — number, все внутри `createChanges`. `revision(area)` возвращает соответствующий номер. `emit` вызывает mark и flush при depth=0; flush очищает bit перед вызовами, чтобы reentrant изменения не терялись. `clear` удаляет callbacks/dirty, но сохраняет terminal revisions для удержанных readonly handles; unsubscribe идемпотентен.

```ts
// Внутри createRequestGate:
const controller = new AbortController()
let owned: Run<PlayResult | SwapResult> | null = null
let finished = false
const finish = (): void => {
  if (finished) return
  finished = true
  signal?.removeEventListener('abort', cancel)
  owned = null
}
const cancel = (): void => {
  if (finished || controller.signal.aborted) return
  const run = owned
  controller.abort()
  run?.stop()
  finish()
}
const adopt = (run: Run<PlayResult | SwapResult>): void => {
  if (finished) { run.stop(); return }
  owned = run
  if (controller.signal.aborted || !isCurrent()) run.stop()
}
signal?.addEventListener('abort', cancel, { once: true })
if (signal?.aborted) cancel()
```

Нужные types импортировать из `../index.js`; `current()` возвращает `!finished && !controller.signal.aborted && isCurrent()`. На любом settlement запрос вызывает `finish()` в finally: он удаляет listener и owned reference, но не останавливает успешно завершённый run и не abort signal. Тесты отдельно доказывают finish-without-stop, cancel-with-stop, finish-before-later-parent-abort и идемпотентность. Добавить reentrancy regression: listener `gate.signal.addEventListener('abort', () => gate.finish())` не мешает cancel вызвать stop захваченного Run ровно один раз. Shared acquisition использует stage-owned signal, а не сигнал первого view; отменённый view проверяет gate перед show/adopt. Нельзя эмулировать join reserved raw adds чтением error.message: существующий workaround сохранить до отдельного покрытого улучшения core, не обещать новых concurrency guarantees.

```ts
export function joinReady<T, K>(invokeOwned: () => Promise<T>, identity: () => K) {
  let pending: { key: K; promise: Promise<T> } | null = null
  return (): Promise<T> => {
    const key = identity()
    if (pending !== null && Object.is(pending.key, key)) return pending.promise
    const promise = invokeOwned()
    const entry = { key, promise }
    pending = entry
    const clear = (): void => { if (pending === entry) pending = null }
    void promise.then(clear, clear)
    return promise
  }
}
```
