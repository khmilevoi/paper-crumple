# tools/bake

The bake pipeline and the pack writers. **Nothing here ships.** `pnpm-workspace.yaml` lists
`packages/*` and nothing else, so this directory is not a workspace package, is in no dependency
graph, and cannot reach a tarball — the guarantee is structural rather than a matter of
discipline (spec §13).

## What is here

| File                     | What it is                                                                                        |
| ------------------------ | ------------------------------------------------------------------------------------------------- |
| `pack.py`                | the reference pack writer: grid tables, codecs, frame blocks, manifest                            |
| `test_pack.py`           | its unit tests, run outside Blender                                                               |
| `python.ts`              | resolves the interpreter as `$PYTHON`, then `python3`, then `python`                              |
| `python.test.ts`         | asserts an interpreter exists and that `test_pack.py` is green                                    |
| `packWriter.ts`          | the JS twin of `pack.py`, for tests and the synthetic generator                                   |
| `bytes.ts`               | `firstDifference`, so the three byte comparisons in this directory share one helper               |
| `fixture.test.ts`        | the cross-language format check: pack.py and packWriter.ts must agree byte-for-byte on the binary |
| `packWriter.test.ts`     | asserts the JS pack writer produces byte-identical output to the reference                        |
| `synthetic.ts`           | an analytic stand-in for a bake, so the runtime comes up without Blender                          |
| `synthetic.test.ts`      | verifies the synthetic fixture is deterministic and can be regenerated                            |
| `fixtures/synthetic.bin` | 539 320 B, generated by `synthetic.ts`, **must never ship**                                       |
| `run.mjs`                | the Blender launcher                                                                              |
| `run.test.ts`            | the launcher's pure parts; starts no Blender                                                      |
| `crumple.py`             | the bake itself — Blender 5.2.1 LTS, 4 m 10 s single-threaded                                     |
| `smoke.py`               | one check per Blender API the bake relies on                                                      |
| `scripts.test.ts`        | `py_compile` over `crumple.py` and `smoke.py`, so a copy error is caught without Blender          |
| `foldTable.mjs`          | provenance for `folds.json`; runs only inside the original spike                                  |
| `folds.json`             | the frozen fold table `crumple.py` reads                                                          |
| `folds.test.ts`          | pins the fold table's shape and numbers so an accidental edit fails loudly                        |

## Requirements

- **Python 3** on `PATH` as `python3` or `python`, or named by `PYTHON=<path>`. `pack.py` uses
  the standard library only — `struct`, `json`, `math`, `os` — and needs no Blender.
- **Blender 5.2.1 LTS**, for `crumple.py` and `smoke.py` only. Never needed by any test.

## The cross-language check

The format has three producers and they must agree on one set of bytes (spec §9.2, §11):

1. `pack.py --fixture` writes `tiny.json` / `tiny.bin`;
2. `packWriter.ts` writes the same pack from the same numbers;
3. `packages/motion/test/fixtures/tiny.{bin,json}` is the committed pair both are compared against,
   and the pair `parsePack` is tested with.

Byte equality holds for the binary on all three. It does **not** hold for the manifest, because
Python renders a float as `1.0` where `JSON.stringify` renders it as `1` — so the twin's manifest
is compared to the parsed committed manifest, and the Python writer's is compared byte for byte.
`tiny.json` is 653 B; the design document's §9.2 says 709 B and is stale.

```bash
pnpm vitest run tools/bake/fixture.test.ts tools/bake/packWriter.test.ts
```

All of it is level 1 and runs in `pnpm test` and in CI with no browser and no Blender.

## Running the Python tests directly

```bash
python -m unittest discover -s tools/bake -p "test_*.py" -v
```

Add `-B`, or export `PYTHONDONTWRITEBYTECODE=1`, to keep `__pycache__/` from appearing;
`tools/bake/.gitignore` ignores it either way.

## A real bake (manual)

`run.mjs` finds Blender at `$BLENDER`, falling back to the Windows Steam install — the Windows
path is a convenience default, not a requirement:

```bash
BLENDER=/path/to/blender node tools/bake/run.mjs tools/bake/smoke.py
node tools/bake/run.mjs tools/bake/crumple.py --bucket 2x3 --bending 500 --ball 0.24
```

`-t 1` is not a performance choice: it keeps the cloth solver and the collision loops
single-threaded so two bakes sum in the same order and come out byte-identical. **It cannot be
parallelised**, which is why the 4 m 10 s stays a manual step and Blender is not a CI dependency.
`--python-exit-code 1` turns an uncaught Python exception into a non-zero exit.

Output lands in `tools/bake/out/` (untracked). Copying a finished pack into
`packages/motion/src/packs/<bucket>/` is a deliberate, reviewed step.

## Regenerating the synthetic fixture

Only after a deliberate change to `synthetic.ts` or to the format:

```bash
WRITE_SYNTHETIC=1 pnpm vitest run tools/bake/synthetic.test.ts   # bash
$env:WRITE_SYNTHETIC=1; pnpm vitest run tools/bake/synthetic.test.ts   # PowerShell
```

Then re-run it **without** the variable: that run is the assertion that the generator is
deterministic across the Node versions CI builds on.

## `folds.json` is frozen

`foldTable.mjs` produced it from the 2D spike (`paper-fold`), which is not part of this
repository; its imports resolve only inside the original spike checkout. The file is vendored as
an input, and `folds.test.ts` pins its shape and its numbers so an accidental edit fails loudly.
